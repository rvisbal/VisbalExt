Cursor Rule: Anatomy Buttons in Salesforce

1. **Container**
   - Rounded corners to contain button contents.

2. **Label**
   - Text that describes the main action or intent of the button.
   - Use Title Case for button labels.
   - Make labels concise, clear, and action-oriented.

3. **Icons**
   - **Left Icon (optional)**: Only utility category icons from SLDS can be used.
   - **Right Icon (optional)**: Only utility category icons from SLDS can be used.

4. **Layout**
   - Place primary actions where they are easy to spot.
   - Secondary actions should be less prominent.
   - Align buttons consistently within forms or action panels.

5. **UI Content**
   - Ensure button labels are concise and clear.
   - Describe actions clearly.

6. **Behaviors**
   - **Default**: Button is ready for interaction.
   - **Hover**: Changes appearance to indicate interactivity.
   - **Active**: Changes appearance when clicked, remains active if a menu, popover, or panel is triggered.
   - **Focus**: Distinct style for keyboard navigation, indicating readiness for user input.
   - **Disabled**: Indicates an inactive or unavailable action.
   - **Loading**: Show a loading spinner for actions requiring processing time.

7. **Responsive Design**
   - Buttons should adapt to screen size for usability on mobile and desktop.
   - Mobile buttons should be optimized for smaller screens and thumb-friendly interactions.

8. **Inverse Buttons**
   - Designed for use on dark or colored backgrounds.
   - Feature white text with a white border for readability.
   - Maintain accessibility and usability where default styles may not stand out.

9. **When to Use Inverse Buttons**
   - Use on sections with dark backgrounds.

10. **When Not to Use Inverse Buttons**
    - Avoid on light backgrounds to prevent visual confusion.
    - Do not mix with standard buttons unless there is a clear visual or functional distinction to avoid confusing users about action hierarchy.
